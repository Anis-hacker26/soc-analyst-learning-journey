# 🔐 Windows Security Logs

## Introduction

Windows Security Logs record security-related events generated by the Windows Security Auditing subsystem. These logs are one of the most important sources of evidence for Security Operations Center (SOC) analysts because they capture authentication attempts, account management activities, privilege changes, and other security events.

During incident investigations, Security Logs help analysts answer questions such as:

- Who logged into the system?
- Were there failed login attempts?
- Was an account locked?
- Was a new user account created?
- Were administrative privileges granted?

# What are Windows Security Logs?

The Security Log records events related to authentication, authorization, and auditing.

Unlike the Application or System logs, the Security Log focuses on **who performed an action** rather than **what application or operating system component performed it**.

SOC analysts rely heavily on these logs when investigating account compromise, privilege escalation, and suspicious authentication activity.

---

# Common Authentication Events

## Event ID 4624 – Successful Logon

This event is generated whenever a user successfully authenticates to the system.

### Investigation Question

> Who successfully logged into the system?

---

## Event ID 4625 – Failed Logon

This event is generated whenever a login attempt fails.

Common reasons include:

- Incorrect password
- Invalid username
- Expired account
- Disabled account

### Investigation Question

> Who attempted to log in but failed?

---

## Event ID 4740 – Account Lockout

This event is generated when Windows locks an account after too many failed login attempts.

### Investigation Question

> Which account was locked and why?

# Investigation Workflow

When investigating authentication events, follow this process:

```
User Reports Login Issue
        │
        ▼
Check Security Log
        │
        ▼
Identify Event Provider
        │
        ▼
Review Relevant Event IDs
        │
        ▼
Analyze User, Source IP, and Time
        │
        ▼
Look for Related Authentication Events
        │
        ▼
Determine Root Cause
```

# Brute Force vs Password Spraying

## Brute Force

A brute-force attack targets **one account** with many password attempts.

Example:

```
John
Password1

John
Password2

John
Password3
```

---

## Password Spraying

Password spraying targets **many accounts** using the same password.

Example:

```
John
Spring2026!

↓

Mary
Spring2026!

↓

David
Spring2026!
```

Password spraying is commonly used to avoid account lockout policies.

# Important Fields During Investigation

When reviewing authentication events, pay attention to:

- Event ID
- Account Name
- Source Network Address
- Logon Type
- Status
- Time Generated

These fields help reconstruct the authentication timeline.

---

# Lessons Learned

- Security Logs are the primary source for authentication investigations.
- Multiple failed logins do not automatically indicate an attack.
- Evidence should be collected before reaching conclusions.
- Context is more important than a single Event ID.
- Confidence increases as additional related evidence is discovered.

---

# Key Takeaways

- Authentication investigations begin with the Security Log.
- Event IDs should always be interpreted within their provider.
- Repeated failed logins require contextual analysis.
- Evidence drives conclusions—not assumptions.
